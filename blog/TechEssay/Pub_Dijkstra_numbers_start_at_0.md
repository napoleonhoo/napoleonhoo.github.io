# 计算机基础课：Dijkstra 大神的《为什么数字应该从 0 开始？》

> 相信很多初学计算机的同学都会好奇，为什么计算机里面的编号都从 0 开始，比如数组的 index。计算机领域的大神 Dijkstra 在这篇文章里面给大家详细讲解了这个问题。原文参考：[EWD831 - Why numbering should start at zero](https://www.cs.utexas.edu/~EWD/transcriptions/EWD08xx/EWD831.html)。

在这篇文章里面，Dijkstra 没有直接讨论这个问题，而是先问了一个更基础的问题：**连续整数区间应该如何表示？**

假设要表示整数 `2, 3, ..., 12`，可以采用四种写法：

```text
2 ≤ i < 13
1 < i ≤ 12
2 ≤ i ≤ 12
1 < i < 13
```

Dijkstra 最终选择第一种，即现在大家都在使用的**左闭右开区间**：

```
[a,b)
```

## 为什么是左闭右开？

Dijkstra 的选择不是单凭习惯，他举了下面这几个理由。仍以整数 `2` 到 `12` 为例：

| 写法  | 区间写法     | 不等式写法        |
| --- | -------- | ------------ |
| a   | `[2,13)` | `2 ≤ i < 13` |
| b   | `(1,12]` | `1 < i ≤ 12` |
| c   | `[2,12]` | `2 ≤ i ≤ 12` |
| d   | `(1,13)` | `1 < i < 13` |

### 第一个理由：区间长度等于边界之差

a 和 b 有一个优点——所写出的两个边界之差，恰好等于该子序列的长度。即长度 `11 = 13 - 2 = 12 -1`。

在 a 和 b 中，如果两个子序列相邻，前面的子序列的上界等于后面子序列的下界。如下面两个子序列：`[2, 10)`和`[10, 13)`。

基于这个理由，我们觉得 a 和 b 更好。

### 第二个理由：下界不超出自然数

自然数中存在一个最小的数。如果像 b 和 d 那样排除下界，那么对于一个从最小自然数（0）开始的子序列，所写出的下界就会被迫落入非自然数的领域（-1）。比如 `-1 < i < 3` vs `0 ≤ i < 3`。

基于这个理由，我们觉得 a 和 c 更好。

### 第三个理由：空序列的上界不超出自然数

从最小自然数开始的子序列：如果包含上界，那么当这个序列缩短为空序列时，所写出的上界就会被迫变成一个非自然数。这同样很难看。比如`0 ≤ i ≤ -1` vs `0 ≤ i < 0`。

基于这个理由，我们觉得 a 和 d 中使用的`<`更好。

**综上所述，我们认为 a 方法更好。**

### 第四个理由：一个侧面的案例

 Dijkstra 举了一个实践中的例子，作为一个很有意思的小故事，也摘录如下：
 
 > 施乐帕克研究中心开发的 Mesa 编程语言，针对上述四种写法中的每一种，都为提供了专门的表示法。使用 Mesa 时的大量经验表明，另外三种写法一直都是丑陋代码和错误的来源。

## 为什么编号从零开始？

确定使用左闭右开区间后，长度为 `N` 的序列若从 `1` 编号，下标范围是：`1 ≤ i < N + 1`

若从 `0` 编号，则是更简洁的：`0 ≤ i < N`

更本质地说，**元素的下标等于它前面已有的元素数量**：第一个元素前面有 `0` 个元素，因此下标为 `0`；第二个元素前面有 `1` 个元素，因此下标为 `1`。

这个定义也直接体现在常见的循环中：

```cpp
for (int i = 0; i < N; ++i) {
    process(sequence[i]);
}
```

当 `N=0` 时，条件 `i < N` 第一次判断就不成立，循环自然执行零次，无须为“空序列”增加特殊分支。

## 总结

从 0 开始编号，确实和我们的日常习惯不同，但是在计算机领域中常见的一些场景中，使用这种方法，是最简洁、最不容易出错、最简单的方法。
